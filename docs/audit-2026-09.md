# Codebase audit — September 2026

A full-logic review of `simulation/` (Rust, ~30k lines), `client/`
(TS/React), `desktop/` (Electron) and `lab/` (Python), run as 20
independent deep-read passes plus adversarial re-verification of the
top findings. Clippy was clean before and after, so essentially
everything below is a *semantic* defect that no lint in the repo
catches.

Two numbers frame the result:

- **~150 distinct findings**, of which **~20 are data-loss or
  correctness criticals**.
- **The test suite passed 336/336 before any of this.** A green suite
  coexisted with a simulation that could not reproduce its own seed, a
  vocabulary that emptied itself, and a save file that silently
  discarded the world's biome history.

---

## Part 1 — Fixed in this PR

### 1.1 Simulated worlds could not be reproduced from a seed (CRITICAL)

`simulation/README.md` advertises `--seed 42` and `--sweep-seeds 5`
("verify that the world remains healthy across seeds"), and three
comments in `choose_action.rs` assert the sim RNG "remains seeded,
preserving reproducible worlds". All of it was false. Measured on the
pre-fix binary, same seed, same machine:

```
run A  1000: 120 alive, 37 animals, 26 fire, 94 shelter, 18 lineages
run B  1000: 120 alive, 34 animals, 14 fire, 90 shelter, 13 lineages
```

Three independent causes, all fixed:

| Cause | Sites |
|---|---|
| Organism/lineage/conversation ids minted from `Uuid::new_v4()` (OS entropy). Ids are not cosmetic — they are hashed into wander schedules (`organism.rs:1075`, `wander.rs:176`), wedding slots (`moments.rs:868`), reflection slots, and the vocabulary seed on load (`persistence.rs:540`). | `spawn.rs`, `growth.rs`, `courtship.rs`, `command.rs` — all 8 sites now use a new `seeded_id(&mut rng, len)`; `uuid` dropped from `sim-core/Cargo.toml` entirely so it cannot regress |
| `std` `HashMap`/`HashSet` iteration order deciding outcomes while drawing from `sim.rng` | `physics/engine.rs` (fire spread — 4 processes with the same seed produced 60/61/62/66 fires), `tech_progress.rs`, `warfare.rs` ×2, `civ_tick.rs` ×5, `moments.rs` (friend gravitation) |
| `max_by`/`max_by_key` returning the last maximum, so ties resolved by hash order | `warfare.rs` (raid target), `civ_tick.rs` (schism parent, dominant religion), `organism.rs` (friend eviction) |

Also fixed inside `tech_progress.rs`: the researcher picker called
`rng.random()` *inside* a `max_by` comparator, so the number of RNG
draws depended on the comparator's internal call pattern rather than on
the roster. Jitter is now drawn once per candidate up front.

**Verified after the fix** (`--ticks 300 --seed 42`, 3 runs): the
behaviour histogram, population, deaths, and gift/challenge counts are
byte-identical. Two regression tests added
(`same_seed_produces_the_same_generated_world`,
`same_seed_yields_the_same_rng_stream`).

**Residual long tail — not fixed, needs a follow-up.** Secondary
counters still diverge at ~300 ticks (e.g. `shelter` holders 28 vs 30),
so some further hash-ordered or ambient-state dependency remains. The
generated world, id assignment and RNG stream are now pinned by tests,
which is the precondition for bisecting the rest.

### 1.2 `grid.biome` was mutated at runtime but never saved (CRITICAL — data loss)

`GridSave` (`persistence.rs:19`) had no `biome` field, but
`world_events.rs:811-864` and `civ_tick.rs:2392` rewrite biomes at
runtime (forest→grassland for farmland, grassland→desert in drought,
grassland→wetland, river/lake formation). Every reload regenerated the
biome map from the seed and silently discarded all of it.

Compounding: `grid.rs:392` caps fertility regrowth at
`Biome::base_fertility()`, and desert is `0.12` against grassland's
`0.72`. So a tile that desertified and then recovered to fertility 0.6
was re-capped to 0.12 on the first decay pass after any reload — and the
regression compounded on every save/load cycle.

`biome` is now serialised and restored under the same length check as
every other grid layer.

### 1.3 Every organism's vocabulary was erased by age ~5100 (CRITICAL)

`Vocabulary::last_used` was initialised to all zeros by `generate`,
`inherit_from` and `from_hashmap`, and `decay()` read `0` as "last used
at tick 0". `decay_memory(tick, 5000)` runs every 100 ticks, so at age
5100 every concept the organism had not personally spoken about was
wiped. `word_for` then silently falls back to the English concept name,
so the organism appears to have lost its language.

Measured census on the pre-fix binary (`Simulation::new(99)`, 418
concepts), mean words per organism:

```
tick      0  418      tick   8000  289      tick  20000  ~3.6
tick   5000  418      tick  12000   33
```

Three compounding defects:

1. `decay` treated "never used" as "used at tick 0". It now starts the
   forgetting clock on first observation.
2. `last_used` was **not persisted at all** — the custom serde impl
   round-trips through `HashMap<String, String>`, so every save/load
   reset it to 0 and a reloaded world lost its whole population's
   vocabulary within 100 ticks of age. It now rides along under a
   reserved `__thb_last_used` key, which older readers ignore.
3. `converge_with` re-granted forgotten words but never touched them, so
   the very next `decay_memory` (which runs *later in the same tick*)
   deleted them again — the convergence was a no-op. It now takes `tick`
   and touches what it writes. Its majority pick was also
   hash-order-dependent.

Added `Vocabulary::known_word()` returning `Option<&str>`, and used it
in `social.rs`: `word_for` returns the concept name when the word is
forgotten, so two organisms who had both forgotten "food" compared
**equal** and counted as recognising each other's signal. They now
correctly fail to recognise, and the narration prints `~` rather than
the English word.

### 1.4 `Traits` had no `#[serde(default)]` (HIGH — one field from total world loss)

`Traits` sits inside every `OrgSave` and was the only struct in the save
graph without a container default. Adding one trait would make every
existing save fail to parse — and the load path answers a parse failure
by starting a brand-new world (finding 1.10). Now defaulted.

### 1.5 Infection decayed twice per tick (HIGH)

`simulation.rs:2928` applied `*= 0.997` and then the `med_mult` block at
`:2933-2943` multiplied again, with `else => 0.997` as its default.
Measured ratio with no medicine: exactly `0.997² = 0.994009`, so
untreated recovery was ~50% faster than intended and every medicine tier
was shifted by the extra factor. Removed the duplicate.

### 1.6 Drought restoration was hardcoded to 50% (HIGH)

`world_events.rs:434` set `drought.rain_relief = 0` and `:442` then
computed `frac` from `drought.rain_relief`, making `frac` a compile-time
constant `0.5`. The rain-proportional restoration documented in the
comment above it never executed, so every drought permanently converted
half its dried shoreline to scars regardless of rainfall. `git blame`
shows `rain_relief = 0` landed in `205c18ea6` (2026-05-07) and the `frac`
line was added later in `86e6d6474` (2026-05-20) without noticing the
reset 8 lines above.

### 1.7 Organisms walked into fire (HIGH)

`organism.rs:toward()` scored direction steps with only a
`!t.walkable()` gate, and `Tile::Fire` **is** walkable
(`tiles.rs:112`). Ten lines earlier in the same function,
`has_progress_step` excludes fire; so do `navigation.rs:51` and
`animal.rs:252`. Verified: `hazard_at` returns 0 on fire (fire creation
never writes the hazard layer), so no penalty applied either, and
`simulation.rs:2194` accepts the step. Standing in fire costs
`reward -= 0.5` and applies burn damage.

### 1.8 Defensive walls multiplied the defender's *offensive* damage (HIGH)

`warfare.rs:853` applied the `defender_wall_bonus` 1.5× multiplier to
`d_dmg` — the damage the **defender deals**, which is then subtracted
from the **attacker**. Walls granted no mitigation at all, only a 50%
damage-output bonus. The existing test
(`defense_bonus_requires_completed_defender_owned_fortifications`) passes
because it only exercises the two `nearby_*` helper predicates and never
touches `a_dmg`/`d_dmg` — a test whose name claims coverage it doesn't
have. The multiplier now reduces damage taken.

### 1.9 Natural deaths were never witnessed by kin (HIGH)

`simulation.rs:4518,4535` emit event type `"died"`; `moments.rs:2034,2073,2109`
match only `"death"`. The whole "broadcast significant events to nearby
kin" subsystem was dead for the most important event class.

*Note: fixing the string alone is not sufficient.*
`moments.rs:2018` builds `by_name` from **living** organisms only, so a
deceased actor can never be resolved. Left for a follow-up that
introduces a `recent_deaths` ring; the producer side is corrected here
and documented at the call site.

### 1.10 A failed save load silently replaced the player's world (HIGH — not fixed, see Part 2)

`persistence.rs:906-909` answers *any* read error with `Self::new(seed)`
— no backup — and the periodic autosave then overwrites the original
600 ticks later. Parse failures at least rename the file aside, but only
`tracing::warn!` reports it: nothing reaches `/health` or the client.

### 1.11 Path traversal on two of three `/worlds/{hash}` routes (HIGH)

`world_meta_handler` (`routes.rs:318`) and `world_snapshot_handler`
(`:360`) passed the `{hash}` segment straight to
`worlds_dir().join(hash)` with no validation, while the sibling
`world_save_handler` (`:332`) validates the charset and length. Axum
percent-decodes the captured parameter, so
`/worlds/..%2F..%2F..%2Fetc/snapshot` reads outside the worlds
directory. Extracted the existing guard into `validate_world_hash()` and
applied it to all three.

### 1.12 `/health` returned 503 for roughly half of every idle minute (HIGH)

`routes.rs:805` used `latest_full_at` as the liveness signal, but that
timestamp is only written on a **deep full frame** — every 300 ticks
(30 s at the default `TICK_MS=100`) — and the deep-full path is skipped
entirely while no WebSocket client is connected, leaving the
`age_ms > 60_000` idle branch as the only writer. An idle server
therefore reported unhealthy for ~30 s out of every 60 s. Added a
`last_tick_at` heartbeat written every tick and keyed `/health` off it.

### 1.13 The delta wire protocol could not express "cleared" (HIGH)

`merge.ts` treated `null` and `undefined` identically and skipped both,
making the cache merge union-only: once set, a field could never be
removed. Meanwhile `wire.ts` translated the server's `-32768`
"no destination" sentinel into `undefined`, and `partner_ids` is only
emitted when set. A separated or dead partner therefore stayed rendered
as bonded until the next cold frame.

- `mergeDefined` now applies an explicit `null` as a clear.
- `wire.ts` emits `null` for the sentinel.
- `types/index.ts` had `target_x?: number` — the type itself encoded the
  lie. Corrected to `number | null`, which immediately surfaced the
  three consumers that had been relying on it.
- `mergeFrame` no longer requires `length > 0` before honouring
  `organisms_complete`, so an authoritative *empty* frame (total
  extinction) actually clears the roster instead of leaving
  `world.organisms` and the store's `byId` frozen on the last-known
  population.
- `merge.test.ts` and `wire.test.ts` encoded the old behaviour as
  expected and were updated.

### 1.14 3D lit geometry teleported to the world origin (HIGH)

`Buildings3D.tsx` put a continuously-varying `emissiveIntensity` (a
day/night float) into its material cache key. `material` is element 1
of the instanced-mesh `args`, so R3F tore down and rebuilt up to ~130
`InstancedMesh`es **per publish** during the two twilight ramps. Because
`material` was missing from the layout-effect deps, the rebuilt meshes
never re-ran the effect and kept their constructor identity matrices —
so hut hearths, doors and windows piled up at world (0,0,0) until the
next building-list change. Fixed by quantising the key (finite key
space), bounding the pool at 512 with disposal, and adding `material`
to the effect deps as a safety net.

### 1.15 `Inn` and `Bakery` had no 3D mesh at all (HIGH)

`BuildingKind` has 174 variants in Rust; `Buildings3D` covered 172
(21 dedicated + 151 generic). `Inn` has window specs and `Bakery` has
workshop polish, so both rendered floating decorations with no building
underneath. Both added.

### 1.16 Unguarded cold-field access could take down the whole app (HIGH)

The sim strips per-organism cold fields (`traits`, `name`, `lineage_id`,
`discoveries`, …) from periodic "full" frames that still set
`organisms_complete: true`, and `#[serde(skip_serializing_if)]` omits
some keys entirely. A cache entry seeded from such a frame has none of
them. `OrgCard` guarded this; `OrgDetail` (`org.traits.curiosity`),
`OrgSearchModal` (`o.name.toLowerCase()`, first keystroke) and
`CivStatsModal` (the only one of 16 `discoveries` readers without
`?? []`) did not. A throw reached the top-level `ErrorBoundary` and
replaced the entire app. All three guarded.

`OrgDetail` also printed a fabricated `💰 rich · 0` for every rich
organism, because `wealth` is not in the server's `OrgJson`. Removed
the number.

### 1.17 `connect()` could permanently freeze the render loop (HIGH)

`useSimulation.ts` overwrote `wsRef.current` without detaching the
outgoing socket's handlers, and `ws.onclose` did not check whether the
firing socket was still the current one. `onVisibilityChange`
deliberately calls `connect()` while the old socket is
`CLOSING`/`CLOSED`-but-not-yet-fired, so the stale `onclose` then set
`connected` false, discarded the new socket's buffered frames, and set
`bootstrapPendingRef = true` — which nothing clears except a resync
that had already been consumed. `parkSocket` nulls its handlers for
exactly this reason; `connect()` now does too, and `onclose` ignores a
replaced socket.

### 1.18 Electron could become impossible to quit from (HIGH)

`index.ts` used `async` `app.on('before-quit')` / `('window-all-closed')`
listeners. Electron discards the returned promise, and `stopSimOnce`
rejects on purpose when SIGKILL cannot be confirmed — so
`e.preventDefault()` had already run and `app.quit()` was never
reached. Cmd+Q was silently ignored for the rest of the session. Both
handlers now catch and always quit.

Compounding: `startSimOnce` installed `current` *after* the up-to-15 s
`waitForPort`, so a child that died during boot was registered as a
running simulation, and `stopSimOnce` returned early without clearing
it — producing a `preventDefault → quit → preventDefault` hot loop.
Added an `alive` re-check and made the early return clear `current`.

### 1.19 A corrupt `settings.json` orphaned the player's worlds (HIGH — data loss)

`settings.ts` caught **every** read/parse error and returned
`{...DEFAULT_SETTINGS}`, which nulls `saveLocationOverride`. The app then
opened a *different* data root and started a brand-new empty world. It
was self-reinforcing: `settings:set` compares against the same failed
read, sees the defaults as "equal", and writes them over the real file —
permanently destroying the save location, API key and autolaunch flag.
Now only `ENOENT` defaults; anything else throws with an actionable
message.

### 1.20 A crash between two renames orphaned the live world (CRITICAL — data loss)

`world-safety.ts:restoreParkedLiveWorld` renamed `_live` to
`_live.failed-reset-<token>` and *then* renamed the parked marker into
place. Between those two syscalls `worlds/_live` does not exist — and
this function exists specifically to run after a crash. The leftover
`_live.failed-reset-*` matched none of the three recovery scanners
(`.next-`, `.rollback-`, `.reset-`), so the next boot found no live
world, minted a brand-new empty one, and the player's real world sat on
disk unreferenced with no IPC path to reselect it.

The current marker is now *copied* (atomically) rather than renamed
away, so `_live` is never absent. `atomicWriteNewFile` also gained an
`overwrite` option and switched its temp name from `Date.now()` to
`randomUUID()` — two writes in the same millisecond previously collided,
and the losing call's `openSync(..., "wx")` unlinked the *winner's*
in-flight temp file.

### 1.21 The inactivity penalty punishes successful actions (HIGH — needs a design decision, see Part 2)

`organism.rs:1904` applies a `-0.006` penalty to any reward below
`0.006`, and there are **~4,140 handler return values** in the 1-5
thousandths range (3,877 of them exactly `0.005`). Instrumented
measurement over 3,000 ticks / 366,868 `learn()` calls:

```
negative branch  (< 0.0)     : 211573 (57.7%)
inactivity branch ([0,.006)) :  59111 (16.1%)   <- 98.4% are repeats
passthrough      (>= .006)   :  96184 (26.2%)
```

The tell is that **41 action files return exactly `0.006`** — precisely
the value that escapes `< 0.006`. Authors had organically learned to
step around the threshold; `crafts_advanced/retted_flax.rs` does
`ctx.event("life", "retted flax")` (a success) then returns `0.005`, and
learns as `-0.001`.

**I attempted to fix this and reverted it.** The threshold turns out to
be *deliberately calibrated*, not arbitrary: the first-attempt novelty
bonus is `0.004 + curiosity * 0.008`, so a cautious organism (0.1) gets
0.0048 — below the threshold, therefore penalised — while a curious one
(0.9) gets 0.0112 and is not.
`organism_tests::curious_organisms_value_genuinely_new_choices` pins
exactly that split. Changing the threshold to `== 0.0` collapsed the
curiosity gradient and failed that test.

The correct fix needs an explicit success flag plumbed into `learn`
(so the penalty applies to "did nothing" but never to "did something
small"), plus a `--sweep-seeds` before/after because it changes what
the world learns. Left as a documented known wart at the call site
rather than shipped as a drive-by change that trades one regression for
another.

## Part 2 — Found, not fixed (needs a decision or more work)

### Blocking / data loss

- **Save-load failure replaces the player's world** (1.10 above). Needs a
  `Result` return or a sticky `load_degraded` flag surfaced on `/health`
  and to the client, plus refusing to autosave over the original path.
- **A future-schema save is renamed away, not copied**
  (`persistence.rs:912-926`). A v5 binary against a v6 world leaves the
  real world only in `world.save.future-v6`, which nothing ever reads.
- **Non-finite floats serialise to JSON `null`**, which serde's float
  deserializer then rejects — so a *single* NaN among 9 × 180,000 grid
  cells makes the entire save unloadable, landing in 1.10. Verified
  mechanism; no reachable NaN producer found today. Needs an
  `is_finite` sweep in `write_save_to_disk`.
- **`archive_and_reset` and the broadcaster do multi-MB `fsync` + gzip
  inside the sim mutex** (`world_archive.rs:224-312`,
  `main.rs:1205-1237`), directly contradicting the `block_in_place`
  rationale in the comment at `main.rs:734-743`. Monthly rollover and
  `POST /admin/reset-world` stall every reader.
- **`recoverInterruptedFileReplacement` installs an unvalidated rollback
  marker as `_live`** (`world-safety.ts:698-702`) — contents never read,
  never `validateWorldHash`'d, no existence check on the world dir. The
  reset path does all three.

### Correctness

- **Reward threshold** (1.21) — needs a success flag + sweep.
- **Birth credits the mother's partner, not the child's real father**
  (`growth.rs:606`). Below 30 population slots
  `reproduction_partner_index(critical=true)` deliberately ignores the
  bond, so an unrelated male gets `children_count`, the parenthood
  attributes, and a memory bond to a child that isn't his.
- **`challenge_stranger` writes the victim's own tile into its
  `danger_memory`** (`social.rs:381`). `mem_strength` is always > the
  0.4 threshold, so the victim spends 3-5 ticks fleeing *itself*, and
  the entry suppresses its remembered food for ~52,000 ticks.
- **`is_elder` has two writers with conflicting semantics** —
  `civ_tick.rs:610` (everyone past 75% of lifespan) and
  `simulation.rs:1602` (one per lineage). It gates knowledge transfer
  (6% vs 2.5%), attributes and elder actions.
- **Reproduction has no adult gate**; `AgeStage::can_reproduce()` is
  dead code with a unit test, while the live gate is `age > 1000`
  absolute ticks — an `Infant` with `max_age = 20000` reproduces.
- **`apply_conquests` mutates `territory` but never updates the
  documented inverse `tile_owner` map**, so post-conquest occupants get
  hostility toward the loser. `claim_territory:5624` also deletes
  inverse entries another lineage still claims.
- **`tick_building_auras` applies only the first matching aura**
  (`civ_tick.rs:438` unconditional `break`) — a resident between a
  Library and a Hospital gets one, not both.
- **`tick_naming_ceremonies` gates on `o.age == 40` but runs on a `% 8`
  cadence** → ~87.5% of newborns are never named.
- **9 duplicate tech node names** (`mathematics`, `geometry`,
  `philosophy`, `cartography`, `theater`, `heraldry`, `alchemy`,
  `refrigeration`, `antibiotics`). First match wins, so the second's
  era/prereq/rate are unreachable; `geometry` is authored Classical but
  live as Iron. Root cause: `TechNode::unlocks` is written 130× and read
  **zero** times, so the declared unlock graph is never applied.
- **`compress_for_archive` clears `discoveries` and `attributes`** on
  corpses, but `headless.rs` reports "Discoveries (ever, alive+dead)" by
  scanning them — so the number silently drops as bodies are archived.
  `organism_tests.rs:85` asserts the erasure is correct, locking it in.
- **`HomeCanvas` never renders `ctx.fixtures`** — the sim's entire
  home-furnishing system (12-item cap, per-pick life events) is
  invisible while the UI subtitle says "N chosen pieces". 726 lines of
  `home/parts/` are dead.
- **`OrgJson` omits `wealth`, `literacy`, `piety`, `degrees`,
  `diseases`, `specialty`, `religion_id`** which `OrgDetail` and
  `NotableOrgsModal` render — 3 of 10 "notable organism" lenses can
  never match, and ~110 lines of detail UI are permanently blank.
- **`serialize.rs` never emits `festivals` or `active_outbreaks`**
  though the client declares and merges both.

### Test quality

- **No determinism regression test existed.** The two tests a reader
  would take for one (`save_load_preserves_social_continuity_and_rng_stream`,
  `…_organism_cooldowns_for_deterministic_replay`) only assert a *field*
  survives a round trip. Added two that pin the generated world and the
  RNG stream.
- **A test locks in erasure of the world's discovery record** (above).
- `scarcity_migration_uses_configured_season_names` builds no simulation
  and asserts a 2-line `matches!`, using season names that
  `config::SEASONS` never produces.
- `apply_memory_pressure` (which makes a live world's content depend on
  host RSS) and `decay_memory` (which owns the Q-table trim) have **zero
  tests**.
- `max_q_for_actions` test can't distinguish the branch it names (both
  matched values are negative).
- **165 `Simulation::new()` calls** (~29 ms each) mostly to obtain one
  organism; and because ids were random, `position(|o| o.alive)` picked
  a *different* organism every run, so those tests only passed because
  their assertions are permissive. One such test
  (`lonely_org_with_only_distant_friends_stays_put`) broke the moment
  ids became seeded — it now uses a private RNG for its cast instead of
  the ambient `sim.rng`.
- Tie-break tests only assert "both were reached at least once" (32
  seeds, one assertion) — a 99%-biased implementation passes.
- **`SAVE_SCHEMA_VERSION` is duplicated across the Rust/TS boundary**
  with no cross-check: bump Rust to 6 and the whole TS suite stays green
  while the desktop app starts rejecting every world the engine writes.
- **`lab/src/thehumanbox_lab/cli.py` has zero test coverage**, which is
  why the broken pipeline flags in 1.22 survived.
- `merge.test.ts` / `wire.test.ts` encoded the un-clearable-delta bug as
  expected behaviour.

### Perf

- `choose_action` allocates and zeroes **~30 KB of stack per organism
  per tick** (`[f32; 6144]` + `[bool; 6144]`), and `max_q_for_actions`
  allocates another 24 KB on every `learn`.
- `grow_plants` is a full 180,000-cell sweep every physics tick (2 Hz)
  with 4 redundant index computations per cell; its sibling
  `decay_trails` was already converted to an incremental dirty set.
- `tick_building_auras` is an O(organisms × buildings) double loop with
  no index, every 180 ticks.
- `Sun.tsx` allocates a new `FogExp2` + 5 `Color`s **per render**;
  `BigMomentEffects` rebuilds geometry on every render (~250-750
  BufferGeometry recreations/sec) because `args` derive from
  render-time `age`; `Humans3D` runs a regex + string build per
  organism per frame despite a comment claiming an alloc-free loop.
- `Earthquake`/`orbit`: `buildings2d` sprite cache is flushed wholesale
  past 900 entries against an ~11k key space.
- `perf-gate.sh` gates on the **max** of 240 samples on a shared CI
  runner while computing `mean_ms` and discarding it — a single GC spike
  fails the job and a 2× mean regression passes. It also runs a
  350-organism world, so none of the crowd-scale work in
  `docs/crowd-performance.md` is exercised.
